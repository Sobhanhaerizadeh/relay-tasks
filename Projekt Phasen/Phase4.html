03
#20
Login-Daten als JSON-Body statt Query-Parameter
Das Problem: Aktuell schickt man Login-Daten ueber die URL — Passwoerter landen so in Server-Logs und im Browser-Verlauf!
# So sieht es aktuell aus — unsicher!
/auth/login?email=admin@example.com&password=admin123
Deine Aufgabe: Die Route nimmt die Daten als JSON-Body an — einfach das UserCreate Schema als Parameter nutzen. Register-Route genauso pruefen.
def login(request: Request, user: UserCreate):
feature/20-login-body ⚡ Blockiert das Frontend-Login
#21
Einheitliche Fehlerantworten
Das Problem: Aktuell gibt es keine klaren Fehlermeldungen wenn etwas schiefgeht. Deine Aufgabe: Jeder Fehler bekommt eine klare Antwort — so weiss das Frontend immer genau was passiert ist.
# Falsches Passwort oder E-Mail
401 → "E-Mail oder Passwort falsch"

# Ungueltiges oder abgelaufenes Token
401 → "Bitte neu einloggen"
feature/21-error-responses
#22
Task-Routen mit Mock-Daten
Die Idee: Relay dreht sich um Aufgaben — jetzt bauen wir die ersten Task-Routen. Noch ohne Datenbank, die Aufgaben stehen einfach fest im Code.
MOCK_TASKS = [
  {"id": 1, "title": "Login bauen", "status": "done"},
  {"id": 2, "title": "Dashboard bauen", "status": "in_progress"},
]
Deine Aufgabe: Zwei Routen bauen — GET /tasks gibt die Mock-Liste zurueck, POST /tasks nimmt eine neue Aufgabe an. Wichtig: Beide Routen nutzen get_current_user — nur eingeloggte User duerfen Aufgaben sehen. Die Schemas dafuer baut Fatemeh in #23 — erst danach starten!
feature/22-task-routes → nach #23 ⚡ Erster Schritt Richtung Relay-Kern
